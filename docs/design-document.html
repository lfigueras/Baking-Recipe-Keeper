Baking Recipe Keeper

Software Design Document

Android application · Kotlin + Jetpack Compose · Version 1.1 · September 2026

1. Overview

Baking Recipe Keeper is a native Android application for storing and managing baking recipes. Each recipe holds descriptive metadata, a list of ingredients (with amounts and units), an ordered baking procedure, optional tags, and a media gallery of photos and a video. The app supports live serving-size scaling, unit conversion, favorites, a consolidated shopping list, a guided step-by-step “Start Baking” mode, exporting a recipe (PDF, Excel, CSV, or plain text), full data backup/restore, search and filtering, and light/dark theming. All data is stored locally on the device using a relational database, and the interface is built entirely with a declarative UI toolkit. No account or network connection is required.

2. Objectives & Scope

  • Create, view, edit, and delete recipes with ingredients and step-by-step instructions.
  • Scale ingredient quantities automatically based on desired servings, with unit conversion.
  • Mark favorites and organize recipes with custom tags.
  • Attach a gallery of photos and a procedure video to each recipe.
  • Build a consolidated, checkable shopping list from one or many recipes.
  • Guide the bake with a full-screen, screen-on, step-by-step mode.
  • Export a recipe as a styled PDF, Excel workbook, CSV, or plain text saved to the device.
  • Back up and restore all data as a single file.
  • Provide a dashboard with counts, search, and category filtering.
  • Aggregate ingredients across all recipes for an at-a-glance overview.
  • Persist data reliably across app updates via database migrations.
  • Offline-first: no network or account is required.

4. High-Level Architecture

The app follows a unidirectional MVVM pattern. Compose screens observe immutable UI state exposed by ViewModels; ViewModels invoke a repository, which is the single gateway to the Room database. Data flows up as reactive streams; user events flow down as function calls.

UI Layer — Jetpack Compose ScreensHomeScreen, PastryDetailScreen, AddPastryScreen, …
▲ state (StateFlow)    ▼ events
ViewModel Layer (MVVM)HomeViewModel, AddPastryViewModel, PastryDetailViewModel, …
▼
RepositoryPastryRepository, ShoppingListRepository — single sources of truth
▼
Data Access Object (DAO)PastryDao — Room queries
▼
SQLite DatabasePastryDatabase (Room)

The repository exposes recipes as a Flow; when the database changes, the UI updates automatically. Dependencies are supplied through ViewModel factories.

PastryDatabase is the Room database (current version 7). Migrations preserve user data across updates:

MigrationChange
1 → 2Added the ingredients table with a cascade foreign key.
2 → 3Added createdAt / updatedAt to recipes.
3 → 4Added the steps table.
4 → 5Added servings, prep/bake minutes, and difficulty.
5 → 6Added isFavorite; added the tags + pastry_tag tables and the shopping_list_items table.

9. Key User Flows

Add / Edit a recipe

  1. User fills name, category, details, and adds ingredient and step rows.
  2. ViewModel validates (name required; ingredient amounts > 0).
  3. The photo is copied into app storage; the recipe, ingredients, and steps are saved.
  4. The screen returns and a confirmation snackbar appears.

Scale servings

  1. On the detail screen the user changes the servings stepper.
  2. A scale factor is derived and every ingredient amount is recomputed for display.

Reorder procedure

  1. User opens the reorder screen and long-presses a step card to pick it up.
  2. The card lifts and follows the finger; steps swap and renumber live.

Delete a recipe

  1. User confirms in a dialog (destructive action in red).
  2. The recipe and its image are removed; a snackbar confirms on the previous screen.

Export a recipe

  1. From the detail menu the user picks PDF, Excel, or CSV.
  2. The exporter builds the file in memory (styled with the brand palette; the PDF embeds the recipe photo).
  3. A system “Save” dialog opens; the user chooses the location and the bytes are written there.
  4. A snackbar confirms the saved file name.

Build a shopping list

  1. From a recipe the user adds its (scaled) ingredients to the shopping list, or adds items manually.
  2. Duplicate ingredients aggregate; items can be checked off, and checked or all items cleared.

11. Future Enhancements

  • User accounts with cloud sync and multi-device backup (in progress on a separate branch).
  • Recipe import from the web and photo/OCR → recipe.

  • AI assistant for substitutions, troubleshooting, and auto-scaling.
  • Community sharing and a subscription (freemium) tier with premium features.
